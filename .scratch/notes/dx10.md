# Fruity DX10: handover notes

Source: `Plugins/Fruity/Generators/Fruity DX10/Fruity DX10_x64.dll` (Delphi, image base 0x400000).
My Ghidra project and decompiles are in the session scratchpad, which is temporary
(`.../scratchpad/dx10/proj`, `out/r1..r4`, `asm_main.txt`, `all.asm`, `states.txt`, `corpus-before.txt`).

## Confirmed from the DLL (asm or decompile)

- `CreatePlugInstance` 0x734510 -> constructor `FUN_00734ae0`. `TTestPlug` VMT 0x7343f0 over `TDelphiFruityPlug`.
  Slots: Dispatcher 0x734570, SaveRestoreState 0x734940, ProcessEvent 0x734ee0 (only MaxPoly into +0xe0, tempo),
  ProcessParam 0x734f30, Gen_Render 0x736a10, TriggerVoice 0x735e30, Voice_Release 0x736320, Voice_Kill 0x736370,
  Voice_Render (slot 13) 0x7364a0. Parameter update `FUN_00735760`, ratios `FUN_00735660` (coarse) and
  `FUN_00735690` (fine), pitch re-update `FUN_00736800`, voice steal `FUN_00735d90`. Info: 114 params, DefPoly 16.
  +0xe0 (max poly) is 0 unless the host sends FPE_MaxPoly.
- State: i32 version (written as 2; versions 3 and up, and 0x7fffffff, are ignored), then 22 i32 params at +0x1b8.
  v1 = 92 bytes. v2 = 460 bytes: 4 unread bytes, then a 364-byte instrument tab (the same articulation block as
  3x Osc and Fruit Kick, `FUN_00722c50`; defaults in `FUN_00722bc0`). Loading the state kills every voice.
- Params (DFM `TSynthEditorForm`, wheel Tag = index): 0 attack, 1 decay, 2 release, 3-9 mod1 coarse/fine/init/
  dec/sus/rel/vel, 10 vibrato, 11 waveform, 12 mod thru, 13 LFO rate, 14-20 mod2 (same order as mod1),
  21 octave -3..3; all others 0..65536. p = (v-min)/(max-min) as f32. The defaults are "Bright E.Piano"
  (table 0x734e40), which is mda's program 1.
- Every formula in `Derived::of` and `Dx10::start`/`render` in dx10.rs was read from the asm, f32/f64 included.
  Constants: 8.175798915644, 6.9, 40.1, 8.9, 0.2, 2^30 (ratio phase), 0.0002*(44100/rate) depths, 0.001 vibrato,
  8/5/6/7 envelope exps, 0.98 decay cut, 0.5-3p^2 rich, 0.25p^2 modmix, 15707.5 LFO, 0.05776226505,
  velocity = Round(127 ln(10v+1)/ln(21.551182)), env0 = (1.5-p11)*0.0035f*(vel+10), out scale 1.2/env0,
  end threshold 0.0002 (bits compare), menv zeroed below 5.96e-8 at block end.
- Differences from mda: two modulators; the modulators are integer-phase lookups in the host sine table
  (WaveTables[0], phase>>18) instead of mda's recursive sine; the fine ratio uses Round, not trunc; the depths
  scale with 44100/rate; the output is normalised to 1.2 and velocity reaches the level only through the pan law;
  the global LFO steps every 101 samples *per voice* (each voice's counter steps the shared LFO); the mod wheel
  (+0x188) and pitch bend (+0x18c) are never moved from 0 and 1.
- Voices are mixed through the articulation unit (`FUN_00721dc0`/`FUN_00722290`): circular pan law (the plugin's
  own copy at `FUN_005fad90`; only unit init writes its selector) with Final.Pan and Final.Vol*volEnv. Fast LP on
  Final.FCut + tab cutoff/256 + modX is active only when f != 1 or fb != 0. With a default tab: plain pan law and
  no filter. Voice_Release does NOT call the articulation release, so there is no 10 ms declick fade.

## Guessed / not confirmed

- Velocity is linked to volume (Final.Vol = velocity * channel vol), as FL Keys assumes.
- The articulation's Fast LP for notes with mod X < 0 or mod Y > 0 is not built (the DX10 copy `FUN_00720cb0` is unread).
- The corpus notes' mod X/Y values for DX10 channels were not checked.

  fidelity Approximate for a heard tab or a filtering note, and 10 unit tests including a corpus-state test.

  the directwave entry. Its test never listed DX10 as unresolved, so that test is unchanged.
