# Event 225: initial REC values (insert volume, pan and friends)

Read from the FL Studio 2026 loader (`FLEngine_x64.dll`, Ghidra base 0x400000)
and checked against the 165 `.flp` files under `Data/`. Confidence tags:
`loader` means read from the decompiled C, `corpus` means the bytes in the
projects agree, `inferred` means a reading of the code or data that no second
source confirms.

## Record layout

Event 225's payload is a run of 12-byte records. The loader wraps the payload
in a memory stream and hands it to `FUN_00f558e0(list, stream, mode 0, ver,
flags169)`, which copies it into a list with record size 12
(`local_28 = 0xc` for mode 0). Nothing is decoded at this point.

    offset  type  meaning
    0       u32   always 0 in the corpus (550,166 records). Unused by the replay.
    4       u32   REC control ID
    8       i32   value

After the whole file is read, the loader walks the list and calls the REC
dispatcher once per record:

    FUN_01046a70(*(rec + 4), *(rec + 8), 0x10011);     // FUN_00f46490 line 3389

Flag 0x10011 is set-value (1) + refresh control (0x10) + loading (0x10000).

### The REC ID

The dispatcher routes on the top of the ID, then splits the rest. For the
mixer range (`FUN_01046a70` lines 495 to 501, reached for 0x70000000..0x7FFFFFFF
through line 2168 and for 0x80000000..0xEFFFFFFF through line 495):

    uVar7    = param_1 & 0xffff;                  // control number
    local_38 = uVar7 + 0x70000000;                // control number, re-based for the compares
    local_28c = param_1 + 0x90000000 >> 0x10;     // (id - 0x70000000) >> 16
    local_30 = param_1 + 0x90000000 >> 0x16;      // insert index   = (id - 0x70000000) >> 22
    local_34 = local_28c & 0x3f;                  // slot index     = ((id - 0x70000000) >> 16) & 0x3f

So a mixer ID is built as

    id = 0x70000000 + (insert << 22) + (slot << 16) + control

    bits  0..15   control number
    bits 16..21   effect slot, 0..9 (6 bits; only 0..9 are used)
    bits 22..31   insert index 0..501, added on top of 0x70000000 and allowed to
                  carry into bit 31

The insert index is a plain addition, not a masked field. Insert 0 is the
master, 1..500 the inserts, 501 the "current" track (`*PTR_DAT_015e2198` is
502, and the loader's insert-state path special-cases `local_e0 == 0x1f5`).

Seen through the u16 at record offset 6 (`hi16 = id >> 16`):

    hi16 = 0x7000 + insert * 0x40 + slot
    slot   = hi16 & 0x3f
    insert = (hi16 - 0x7000) >> 6

What the "bits 13..15" are: they are the 0x7 range prefix (0x7000 sets bits
12, 13 and 14) plus whatever carries out of `insert * 0x40`. Inserts 64..127
push the sum to 0x8000.., which is why bit 15 appears, and insert 501 gives
0x7000 + 0x7d40 = 0xED40 (bits 13, 14, 15). The corpus matches exactly:
`hi16 >> 13` is 3 for inserts below 64, 4 for 64..127, 7 for insert 501.

The "insert in bits 6..12" view from the dictionary row is therefore wrong
for files written by FL 24.2.99 and later: it reads insert + 64. It is right
for older files, which use a different base (next section).

### Two encodings, remapped by version

Files saved before FL 24.2.99 (and files without event 103) store mixer IDs
with base 0x20000000 instead of 0x70000000, and the current track as insert
126 instead of 501. Same bit layout otherwise. The loader rewrites them before
the replay (`FUN_00f46490` line 3253):

    if ((ver < 0x16e3e33) || (103 not seen))      // 0x16e3e33 = 24002099 = 24.2.99
      FUN_012dfa70(local_68, FUN_00f45460, 0);    // for each record

`FUN_00f45460` (decompiled under `ghidra/out/rec225/`):

    if (id - 0x20000000 < 0x20000000) {                     // 0x2xxxxxxx..0x3xxxxxxx
      ctl = (id & 0xffff) + 0x20000000;
      if (ctl < 0x20001f40 || ctl > 0x20001fbf) id += 0x50000000;   // base 0x2 -> 0x7
      else                                       id += 0x500000c0;   // sends 0x1f40.. -> 0x2000..
      rel = id - 0x70000000;
      if (rel >> 22 == 0x7e)                                         // old current track 126
        id = (id & 0xffff) + 0x70000000 + (((rel >> 16) & 0x3f) + 0x7d40) << 16;  // -> 501
    }

The version integer is major * 1000000 + minor * 1000 + patch; the same
function uses 0x132afb9 = 20099001 for the 20.99.1 cutoff the dictionary
already documents for event 233.

Corpus: every project saved by 24.1.2.4408 or earlier uses the 0x2 base, every
project from 24.2.99.4720 on uses 0x7. No file mixes the two. A reader that
wants one code path can apply the remap above to any ID in 0x20000000..0x3FFFFFFF
and then decode with base 0x70000000.

Three older remaps also run on the list, for files older than 5.3.5, 5.3.7 and
8.5.0 (`FUN_00f457e0`, `FUN_00f45840`, `FUN_00f458e0`). They shift a few
control numbers and multiply pre-5.3.7 volumes by 100. None of the corpus
files is that old, so they are listed only for completeness.

## Per-insert controls

Control number is `id & 0xffff`. Every record below lives at slot 0 unless
noted. "Default" is the value the master insert carries in `Empty.flp`; the
other 33 new-encoding projects agree for every control.

| control | name | storage in the insert struct (stride 0x1478 from `PTR_DAT_015e06a0`) | raw range | scaling | default | confidence |
|---|---|---|---|---|---|---|
| 0x1FC0 | volume | `+0x384` (`900 + 0*4`) | 0..16000, clamp table `DAT_01549cb4/b8` | 12800 = unity (0 dB). Hint: `v / 12800.0`, then `dB = 20 * log10(gain(v))`, see curve below | 12800 | loader, corpus |
| 0x1FC1 | pan | `+0x388` (`900 + 1*4`) | -6400..6400, clamp `DAT_01549cbc/c0` | 0 = centre. Hint formatter gets `v + 0x1900` over 0x3200, i.e. the same 0..12800 pan display channels use | 0 | loader, corpus |
| 0x1FC2 | stereo separation | `+0x38c` (`900 + 2*4`) | -64..64, clamp `DAT_01549cc4/c8` | `v / 64.0` formatted by `FUN_006a4ac0` as "%d%% separated" below 0, "%d%% merged" above, "Original" at 0 (`docs/mixer-insert.md`) | 0 | loader, corpus |
| 0x1FD0 + b | EQ band b gain, b = 0..2 | `+0x1d4 + b*0x88 + 0*4` | -1800..1800 (the mixer form's slider; no clamp in the set path) | `v * 0.01` dB (`*PTR_DAT_015e4bc8` = 0.01), hint appends "dB" | 0 | loader, corpus, form |
| 0x1FD8 + b | EQ band b frequency | `+0x1d4 + b*0x88 + 1*4` | 0..65536 (the form's wheel) | `(101^(v/65536) - 1) * 159.9 + 10` Hz, 10 Hz to 16 kHz, kept at band `+0x18` (insert `+0x1ec` for band 0) by `FUN_0127b390`; `docs/mixer-insert.md` | 5777, 33145, 55825 (FL's 90 Hz, 1.5 kHz, 8 kHz bands) | loader, corpus |
| 0x1FE0 + b | EQ band b bandwidth | `+0x1d4 + b*0x88 + 2*4` | 0..65536 (the form's wheel) | `v / 65536` (`*PTR_DAT_015e4a08` = 1/65536) shown with 2 decimals; a shelf's slope or a peak's Q, `docs/mixer-insert.md` | 17500 | loader, corpus |
| 0x2000 + d | send level to insert d | `+0x394 + d*8` | 0..16000 (`FUN_01046a30(v, 0, 16000)`) | 12800 = unity; hint uses the volume formatter with 0x3200 as reference | absent unless routed | loader, corpus |
| 0x1F00 | slot s enabled (slot in bits 16..21) | slot object `+0x148` (byte) | 0 or 1 | `v > 0` | 1 for every slot 0..9 | loader, corpus |
| 0x1F01 | slot s mix level | slot object `+0x138` | 0..12800 | 12800 = 100 % | 12800 for every slot 0..9 | loader, corpus |
| 0x8000 + n | plugin parameter n of slot s | plugin vtable `+0x30` | plugin-defined | plugin-defined | absent in Empty.flp | loader |

Only 0x1FC0..0x1FC2, 0x1FD0..0x1FE2, and slots' 0x1F00/0x1F01 appear exactly
once per insert in every new-encoding project (34 files, 1796 inserts).
Sends appear only where routes exist.

Volume curve (`FUN_0127b050`, which the set path calls after writing
`+0x384`): raw 0 gives gain 0; raw 0x3200 with pan 0 and separation 0 is
hard-wired to gain 1.0 (or -1.0 when the polarity byte at `+0x390` is set);
anything else is

    g    = v / 12800                                 (*PTR_DAT_015e4780 = 1/12800)
    gain = (exp(g * K) - 1) * 0.1                    (FUN_0040ae70 = exp, inferred;
                                                      *PTR_DAT_015e4420 = 0.1)

`K` lives in `.bss` (`*PTR_DAT_015e0350` points at `0x15f49ec`), and the
initialiser at `0x6a6925` sets it to `(float)ln 11` (`docs/mixer-insert.md`). The hint path in the dispatcher (lines 683 to 702) does
the same computation and then `20 * log10(gain)` with `_DAT_0104cd50` = 20.0.

Pan law and separation are applied in the same function: pan goes through
`FUN_006a3a00(L, R, pan * *PTR_DAT_015e4d70, gain * *PTR_DAT_015e3800)`,
separation adds a linear term for negative values and an exponential one for
positive. `docs/mixer-insert.md` has the whole matrix, polarity and swap
with it.

After a volume or pan write the dispatcher also calls
`FUN_012c1960(insert, 6)` for 0x1FC0 and `(insert, 7)` for 0x1FC1, which
notifies all ten slot plugins (`FUN_0132f710(slot, 6|7)`). That is the only
place the two IDs are told apart, which is why volume and pan get the
"notify" treatment and separation does not.

## Other scopes carried by 225

Global: every project in the corpus carries exactly one record with
ID 0x40000000, the main volume (`*PTR_DAT_015e36d8`, default 12800, same
curve as insert volume). No 0x40000001 (shuffle), 0x40000002 (pitch) or
0x40000005 (tempo) record appears in 225; the loader refreshes
0x40000000..0x40000002 itself after the replay (`FUN_01046a70(id, 0, 0x1a)`,
loader line 3430).

Channel: none. Zero records in the corpus have an ID below 0x10000000.
The dispatcher would accept them (channel index = `id >> 16`, control =
`id & 0xffff`; 0 volume 0..12800, 1 pan 0..12800 with 6400 centre, 2 and 3
filter cutoff and resonance, 4 pitch -4800..4800 cents, 7 mute, 0x8000+n
plugin parameters, with 0x100.. 0x600 and 0x1000.. for TS404, delay, arp,
tracking and envelopes). Channel initial values travel in their own events
instead. For `crates/model`, 225 contributes: per insert volume, pan,
separation, three EQ bands, per slot enabled and mix, send levels, and the
main volume. Nothing per channel.

Pattern and playlist ranges (0x5xxxxxxx, 0x6xxxxxxx) do not appear either.

## Insert-state presets (format 0x40)

When the loader reads an insert state file rather than a project, it rewrites
each record's insert index to the target insert before replaying
(`FUN_00f46490` lines 3696 to 3714):

    local_f0 = ((id - 0x70000000) >> 16) & 0x3f;                      // keep the slot
    FUN_01046a70((target * 0x40 + local_f0) * 0x10000 + (id & 0xffff) + 0x70000000, value, 0x11);

and skips 0x1FC0..0x1FC2 when the target is the current track (501), so
loading a preset onto "current" does not overwrite its volume, pan and
separation.

## Corrections from the mixer implementation (crates/model/src/rec.rs, crates/engine/src/mix.rs)

- Send level defaults to 12800, not absent: `FUN_0127b780` sets it at insert reset. Before 11.5.10 the loader zeroes the levels of sends to inserts 100..103.
- "Sends appear only where routes exist" does not hold for old-encoding files.
- The current-insert index is 104, not 126, in projects before 12.9.0 (81 corpus projects); 2,378 records stay on insert 104 after the remap. 126 applies from 12.9.0 to 24.2.99.
- K = ln 11 confirmed: 16000 gives 5.59 dB, and the send handler uses the same curve.
- Routing comes from event 235 (byte i is a send to insert i) on top of the default send to master. Insert disabled is bit 3 of the 236 flags (or of event 27 in files with a 5-byte 236), read from `FUN_012c1810`.

## Gap found while writing records (crates/model/src/mixer_edit.rs)

The legacy remap moves insert 126 to 501 but leaves send destination 126 alone, yet 6,350 legacy records address destination 126 (and 2,310 address 104). No corpus file repeats a target, so last-wins never arises there. Appended records use the loader's own gate for the encoding (base 0x20000000, sends at 0x1F40, current track 126 before 24.2.99 or without a 103); re-encoding all 550,166 corpus records reproduces every ID.

## Sidechain routes (crates/engine, crates/model/src/mixer.rs)

Nothing in event 235 marks a sidechain: its bytes are 0 or 1 in every project. A sidechain is an ordinary route whose 225 send level (0x2000 + dest) is 0. A plugin's "sidechain input N" is the Nth insert routed into its own insert, in rising order, counting audible routes as well. Corpus: of 175 Limiter slots with an input set, 162 land on a level-0 route, 12 on an audible one, 1 has no source. The Stereo Shaper's "sidechain output" is not a source: `FUN_0132bb50` (GetOutBuffer) hands it the destination insert's own buffer, so the difference signal is added to that bus. Inferred: the sidechain signal is taken after the source's volume and pan (GetInBuffer not decompiled).

## Correction from the channel controls (docs/rec-channel.md)

`FUN_01046a30(v, min, max)` is no clamp: it is `min + round(v * 2^-30 *
(max - min))`, the scale from a normalised value (flag 0x20) onto a fixed
range. The channel controls, their storage and their ranges are mapped in
`docs/rec-channel.md`: 2 and 3 are the channel's mod X and mod Y, which
drive the sampler's filter cutoff and resonance, 4 the pitch knob, 0x10 to
0x14 the 229 level adjustments, 0x300 the arpeggiator, 0x500 tracking,
0x600 an automation clip's LFO and 0x1000 the envelopes.

## The slot bits of an insert's own control (crates/engine/src/automation.rs)

The dispatcher's mixer branch (`FUN_01046a70` from 0x104aac7) works the
slot out of every mixer ID, but reads it only for 0x1F00 and 0x1F01 (the
slot object at `insert + 0x134c + slot * 8`) and for a plugin parameter
(0x8000 on). Volume, pan and separation (0x1FC0..0x1FC2, `insert + 900 +
n * 4`), the EQ and the sends index the insert alone. So an ID like
`0x7000_0000 + (65 << 22) + (9 << 16) + 0x1FD8` drives insert 65's first
EQ band, and the slot is ignored. `RecTarget::decode` keeps the slot of
such an ID, and the engine drops it before it looks the control up.
Corpus: 11 clips of `Bombs Away ft KARRA - I'm Awake.flp` drive an EQ
band's frequency (0x1FD8, 0x1FDA) through slot 9.
